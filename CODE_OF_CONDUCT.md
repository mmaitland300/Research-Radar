# Code Of Conduct

Research Radar is a solo-maintained public prototype, but issues and pull
requests should still be usable for focused, respectful technical review.

## Expected Behavior

- Be direct about bugs, evidence, and limitations without attacking people.
- Keep feedback specific enough to act on: name files, commands, routes, run ids,
  or docs when possible.
- Respect the project's scope. It is acceptable to say that a claim needs better
  evaluation evidence; it is not useful to remove limitations without evidence.
- Do not post secrets, private data, database dumps, raw provider payloads, or
  exploit details in public threads.

## Unacceptable Behavior

- Harassment, insults, threats, or personal attacks.
- Repeated off-topic comments after a maintainer asks to narrow the discussion.
- Publishing private credentials, personal information, or non-public data.
- Misrepresenting prototype results as validated production claims.

## Reporting

For normal bugs or documentation problems, use the issue templates.

For security-sensitive reports, follow `SECURITY.md` and avoid posting exploit
details publicly.

## Enforcement

The maintainer may edit, hide, lock, or remove comments and issues that make the
project harder to review safely. Repeated or severe violations may be reported
through GitHub's platform moderation tools.
